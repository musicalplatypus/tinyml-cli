# Plan 08-01: Add --dataset-preset Flag + Builder Wiring

## Objective

Add a `--dataset-preset` flag to `train` and `run` subcommands and wire it into the config
builder so users can select a named dataset preset without writing a full YAML config.

## Background

`run_tinyml_modelmaker.py` reads `config['dataset']['dataset_name']` and resolves it via
`ModelRunner.get_dataset_preset_descriptions()`. The builder currently hardcodes `"default"`:

```python
# mmcli/builder.py ~line 79
"dataset": {
    "dataset_name": "default",
    ...
}
```

There is a `--dataset` flag on the `init` subcommand (for downloading sample datasets) but
nothing analogous for `train`/`run`. Users wanting e.g. `motor_fault_sample` as a dataset
preset must provide a hand-written YAML.

## Tasks

### Task 1: Add --dataset-preset to training args

<read_first>
- mmcli/cli.py (_add_training_args function)
</read_first>

<action>
In `_add_training_args`, add after the `--feature-extraction` argument block:

```python
group.add_argument(
    "--dataset-preset",
    dest="dataset_preset",
    metavar="PRESET",
    default=None,
    help=(
        "Dataset preset name. Default: 'default'.\n"
        "Use 'mmcli info -m <module> -t <task>' to list available presets.\n"
        "Examples: motor_fault_sample, arc_fault_sample"
    ),
)
```
</action>

<acceptance_criteria>
- `python -m mmcli train --help | grep -A3 "dataset-preset"` shows the flag and description
- `python -m mmcli run --help | grep "dataset-preset"` exits 0
- `python -m mmcli compile --help | grep "dataset-preset"` — compile does not add this flag
  (dataset is irrelevant for compile-only workflows)
</acceptance_criteria>

---

### Task 2: Wire --dataset-preset into builder.py

<read_first>
- mmcli/builder.py (the `build_config` function, specifically the feature_extraction_name wiring block)
</read_first>

<action>
In `mmcli/builder.py`, locate the block that wires `feature_extraction_name`:

```python
_set(config,
     "data_processing_feature_extraction",
     "feature_extraction_name",
     getattr(args, "feature_extraction", None),
)
```

Immediately after it, add:

```python
_set(config,
     "dataset",
     "dataset_name",
     getattr(args, "dataset_preset", None),
)
```

The `_set` helper only updates the config when the value is not None, so omitting
`--dataset-preset` keeps the existing `"default"` in place.
</action>

<acceptance_criteria>
- When `args.dataset_preset = "motor_fault_sample"`, the resulting config dict has
  `config["dataset"]["dataset_name"] == "motor_fault_sample"`
- When `args.dataset_preset = None` (flag omitted), `config["dataset"]["dataset_name"]`
  retains its prior value (`"default"` from the template)
- `python -c "from mmcli.builder import build_config; print('ok')"` exits 0
</acceptance_criteria>
