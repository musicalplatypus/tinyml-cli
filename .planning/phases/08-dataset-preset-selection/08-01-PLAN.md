# Plan 08-01: Add --dataset-preset Flag + Builder Wiring

## Objective

Add a `--dataset-preset` flag to `train` and `run` subcommands and wire it into the config
builder so users can select a named dataset preset without writing a full YAML config.

## Background

`run_tinyml_modelmaker.py` reads `config['dataset']['dataset_name']` and resolves it via
`ModelRunner.get_dataset_preset_descriptions()`. Currently the builder sets `dataset_name` in
the `_SKELETON` to `"default"` but this is immediately overridden by:

```python
# builder.py lines 162–170 (project_dir block)
if project_dir:
    _set(config, "dataset", "dataset_name", os.path.basename(project_dir))
```

For the default `--project data/projects/default`, this resolves to `"default"` via
`basename()` — so effective behaviour matches the skeleton default, but the mechanism
matters: the `--dataset-preset` wiring must come AFTER the project_dir block to override it.

Users wanting e.g. `motor_fault_sample` as a dataset preset currently need a hand-written
YAML. `--dataset-preset` closes this gap.

## Tasks

### Task 1: Add --dataset-preset to training args

<read_first>
- mmcli/cli.py (_add_training_args, lines 345–430, specifically the --feature-extraction block at lines 358–376)
</read_first>

<action>
In `_add_training_args`, after the closing parenthesis of the `--feature-extraction`
`add_argument` call (after line 376), add:

```
group.add_argument(
    "--dataset-preset",
    dest="dataset_preset",
    metavar="PRESET",
    default=None,
    help=(
        "Dataset preset name. Default: 'default'.\n"
        "Use 'mmcli info -m <module> -t <task>' to list available presets.\n"
        "Examples: motor_fault_sample, arc_fault_sample"
    ),
)
```
</action>

<acceptance_criteria>
- `python -m mmcli train --help | grep -A3 "dataset-preset"` shows the flag and description
- `python -m mmcli run --help | grep "dataset-preset"` exits 0
- `python -m mmcli compile --help | grep "dataset-preset"` exits non-zero (flag not present in compile)
</acceptance_criteria>

### Task 2: Wire --dataset-preset into builder.py

<read_first>
- mmcli/builder.py (build_config, lines 155–180 — the project_dir block AND the feature_extraction wiring block immediately after it)
</read_first>

<action>
In `build_config`, locate the feature_extraction wiring block (lines 173–178):

```python
_set(
    config,
    "data_processing_feature_extraction",
    "feature_extraction_name",
    getattr(args, "feature_extraction", None),
)
```

Immediately AFTER this block, add:

```python
_set(config,
     "dataset",
     "dataset_name",
     getattr(args, "dataset_preset", None),
)
```

Placement after the project_dir block (lines 162–170) is required — the `_set` helper
skips when value is None, so omitting `--dataset-preset` preserves the basename-derived
`dataset_name`. Providing a preset overrides it.
</action>

<acceptance_criteria>
- When `args.dataset_preset = "motor_fault_sample"`:
  `config["dataset"]["dataset_name"] == "motor_fault_sample"`
- When `args.dataset_preset = None` (flag omitted):
  `config["dataset"]["dataset_name"] == "default"` (basename of default project dir)
- `python -c "from mmcli.builder import build_config; print('ok')"` exits 0
</acceptance_criteria>
