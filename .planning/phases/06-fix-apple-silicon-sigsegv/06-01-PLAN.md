# Plan 06-01: Document and Mitigate onnxsim Shutdown Crash (macOS ARM64)

## Root Cause (confirmed)

`onnxsim_cpp2py_export.cpython-310-darwin.so` performs a null-pointer dereference in its C++
destructor during Python interpreter teardown on macOS ARM64. This fires **after** the pipeline
completes and all artifacts are written — it is a benign shutdown crash, not a functional failure.

- **Exit code:** 245 (= -11 mod 256 = SIGSEGV)
- **Cannot be caught** by `try/except` — fires during interpreter teardown, outside Python's error handling
- **No output corruption:** `mod.a`, `model.onnx`, and all quantization artifacts are written before the crash
- **Not related to** NumPy/Pandas/OpenMP architecture mismatches (those are a separate class of issue)

## Strategy: Option A — Accept and Document

The correct fix is to accept exit code 245 as a success indicator on macOS ARM64 and document
the behavior so users and developers are not alarmed. This is already implemented; this plan
verifies and records the implementation.
