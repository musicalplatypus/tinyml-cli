# Plan: Fix Python SIGSEGV crash on Apple Silicon

## Context
- Crash is a SIGSEGV data abort at address 0x10 inside CPython while executing bytecode.
- Stack shows native extensions (NumPy, Pandas) causing NULL‑pointer dereference, likely due to mismatched binary wheels or OpenMP library.
- No multiprocessing code in repo; semaphore warning originates from internal library usage.

## Steps
1. Remove any existing virtualenv and create a fresh arm64 venv.
2. Upgrade pip/setuptools/wheel.
3. Install Homebrew `libomp` and `ffmpeg`.
4. Export `DYLD_LIBRARY_PATH` to point at Homebrew libomp.
5. Reinstall project in editable mode, forcing arm64 wheels for NumPy & Pandas.
6. Install optional heavy libs (`torch`, `opencv-python-headless`) using Apple‑silicon compatible wheels.
7. Run a small script with `faulthandler` that imports each native extension individually; confirm no crash.
8. If a module crashes, inspect its linked libraries via `otool -L`; replace any x86_64 references.
9. Add a multiprocessing guard (set start method to `spawn`) when invoking the CLI, if hidden library uses multiprocessing.
10. Run full training/quantization pipeline; verify no crash and that quantization metrics improve.
11. Persist `DYLD_LIBRARY_PATH` in the venv activation script for future sessions.

## Verification
- All import tests succeed without segmentation fault.
- Full pipeline finishes, generating `model.onnx` and printing quantization summary.
- Quantization metrics (SNR/PSNR) become non‑negative or improve relative to baseline.
- No “leaked semaphore objects” warning appears at shutdown.
