# Plan 01-03: Testing Infrastructure

## Goal

Establish pytest-based testing infrastructure with centralized fixtures, CI integration,
and basic unit test coverage for core CLI components.

## Problem

After the initial implementation the project had no test directory, no conftest.py, and no
CI. Security hardening required a way to verify `_is_safe_path()` and `_sanitize_input()`
behavior. The adversarial review also identified the need for regression coverage of core
CLI argument parsing and configuration building.

## Tasks

### Task 1: pytest configuration
<files>pytest.ini, conftest.py</files>
<action>
Create pytest.ini with testpaths=tests, addopts for coverage, and marker declarations.
Create conftest.py with shared fixtures:
- python_exe fixture (returns MMCLI_PYTHON env var or a mock path)
- tmp_project fixture (creates a temp directory with minimal project structure)
- psutil fallback (mock psutil if not installed, for resource-check tests)
</action>

### Task 2: CLI argument parsing tests
<files>tests/test_cli_parsing.py</files>
<action>
Create tests/test_cli_parsing.py covering:
- Subcommand routing (train/compile/run/info/init each parse to correct handler)
- Required argument detection (--device, --project required for relevant commands)
- --config override parsing
- --help exits 0
</action>

### Task 3: Configuration builder tests
<files>tests/test_config_builder.py</files>
<action>
Create tests/test_config_builder.py covering:
- build_config generates correct YAML structure for train task
- build_config generates correct YAML structure for compile task
- Compilation section populated correctly from --onnx-model flag
- dataset section populated from --project path
</action>

### Task 4: Cross-platform and environment tests
<files>tests/test_cross_platform.py, tests/test_environment_integration.py</files>
<action>
Create tests/test_cross_platform.py:
- Path separator handling (Windows vs POSIX)
- _is_safe_path behavior on platform-specific path formats

Create tests/test_environment_integration.py:
- MMCLI_PYTHON env var resolution
- MMCLI_MODELMAKER env var resolution
- Behavior when env vars are missing (graceful error)
</action>

### Task 5: GitHub Actions CI
<files>.github/workflows/ci.yml</files>
<action>
Create .github/workflows/ci.yml:
- Trigger: push and PR to main
- Matrix: ubuntu-latest, macos-latest (Windows as continue-on-error)
- Steps: checkout, setup Python 3.10, pip install deps, pytest --tb=short
- Upload coverage report as artifact
</action>

## Success Criteria

- `pytest tests/ -v` runs without import errors
- test_cli_parsing.py: all subcommand routing tests pass
- test_config_builder.py: build_config produces valid YAML structure
- conftest.py: tmp_project fixture creates isolated temp directory
- GitHub Actions CI passes on ubuntu-latest and macos-latest
- Coverage report generated
