# Plan 01-02: Security Hardening (Input Validation & Subprocess Isolation)

## Goal

Harden the CLI against the attack surface identified in the adversarial review:
- Path traversal via `--project` and other path arguments
- Command injection via unsanitized string inputs reaching subprocess
- Overly permissive subprocess invocation

## Problem

The initial implementation passed user-supplied strings (project paths, device names, task types)
directly into config dicts and subprocess argument arrays without validation. ADVERSARIAL_REVIEW.md
identified:

1. **Path traversal** — `--project ../../../etc` could escape the working directory
2. **Command injection** — input strings with backticks/semicolons/$ reaching subprocesses
3. **No input length limits** — no protection against buffer-overlong strings

## Security Architecture

All user inputs pass through two gates before use:

```
user input → _is_safe_path(path)        → reject if .. / starts with / / dangerous chars
user input → _sanitize_input(input_str) → strip dangerous chars, enforce 1024-char limit
```

The subprocess pattern is hardened by:
- `shell=False` everywhere — no shell metacharacter expansion
- Argument arrays (never string concatenation) for all subprocess calls
- MMCLI_PYTHON validated as a real executable path

## Tasks

### Task 1: _is_safe_path() implementation
<files>mmcli/cli.py</files>
<action>
Add _is_safe_path(path: str) -> bool to mmcli/cli.py.
Block:
- ".." anywhere in path (path traversal)
- Absolute paths starting with "/" (escape from working directory)
- Paths with dangerous characters (not in [a-zA-Z0-9_\-./ ])
- Empty strings
Return False immediately on any violation; return True only if all checks pass.
Apply to all --project, --dataset, --output-dir, and file path arguments.
</action>

### Task 2: _sanitize_input() implementation
<files>mmcli/cli.py</files>
<action>
Add _sanitize_input(input_str: str) -> str to mmcli/cli.py.
Strip characters not in [a-zA-Z0-9_\-./ ].
Remove all ".." sequences iteratively until none remain.
Strip backticks, dollar signs, semicolons.
Truncate to 1024 characters.
Apply to device names, task types, model names, and other non-path string inputs.
</action>

### Task 3: Enforce shell=False + argument arrays
<files>mmcli/cli.py</files>
<action>
Audit all subprocess.run calls in cli.py.
Ensure every call uses shell=False and passes a list, not a string.
Ensure MMCLI_PYTHON is validated (os.path.isfile check) before first use.
</action>

### Task 4: Security test suite
<files>test_security_fixes.py, tests/test_security.py</files>
<action>
Create test_security_fixes.py with tests validating:
- _is_safe_path rejects "../", "/etc/passwd", empty string, paths with $
- _is_safe_path accepts "myproject", "data/train", "model-v1"
- _sanitize_input strips backticks, semicolons, dollar signs
- _sanitize_input truncates at 1024 chars
- subprocess calls use shell=False
</action>

## Threat Model

| Threat | Mitigation |
|--------|-----------|
| Path traversal (REQ-SEC-01) | _is_safe_path() blocks ".." and absolute paths |
| Command injection (REQ-SEC-02) | _sanitize_input() + shell=False + argument arrays |
| Buffer overflow (REQ-SEC-03) | 1024-char length limit in _sanitize_input() |
| Env var manipulation | MMCLI_PYTHON validated as executable before use |

## Success Criteria

- `_is_safe_path("../../../etc")` returns False
- `_is_safe_path("myproject/data")` returns True
- `_sanitize_input("rm -rf /; echo")` → "rm -rf  echo" (semicolon stripped)
- All subprocess calls use `shell=False`
- `python test_security_fixes.py` passes
