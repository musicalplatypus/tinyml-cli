# Plan 01-02: Security Hardening (Input Validation & Subprocess Isolation)

## CRITICAL: Phase 5 Regression

`_is_safe_path()` and `_sanitize_input()` were removed from `mmcli/cli.py` in Phase 5
commit `eb0a1bd` during a large cli.py rewrite (564 lines changed). As of that commit:

- Neither function exists anywhere in `mmcli/`
- `test_security_fixes.py` fails at import: `ImportError: cannot import name '_sanitize_input'`
- Path traversal and command injection are **unmitigated** in the current codebase
- `shell=False` still holds (subprocess pattern), but input validation is gone

This regression must be addressed before Phase 1 security hardening can be considered complete.
See "Restoration Required" section at the end of this plan.

---

## Goal

Harden the CLI against the attack surface identified in the adversarial review:
- Path traversal via `--project` and other path arguments
- Command injection via unsanitized string inputs reaching subprocess
- Overly permissive subprocess invocation

## Problem

The initial implementation passed user-supplied strings (project paths, device names, task types)
directly into config dicts and subprocess argument arrays without validation. ADVERSARIAL_REVIEW.md
identified:

1. **Path traversal** — `--project ../../../etc` could escape the working directory
2. **Command injection** — input strings with backticks/semicolons/$ reaching subprocesses
3. **No input length limits** — no protection against buffer-overlong strings

## Security Architecture (Target State)

Inputs are validated through semantic OS-native checks, not string manipulation:

```
user path input  → pathlib.Path(path).resolve()
                   .is_relative_to(Path.cwd())  → reject if escapes CWD
                   check no symlink loops       → reject dangerous symlinks

user string input → enforce length ≤ 1024 chars
                   validate against an allowlist of known-safe values (device IDs,
                   task types) rather than stripping unknown chars
```

The subprocess pattern:
- `shell=False` everywhere — no shell metacharacter expansion
- Argument arrays (never string concatenation)
- MMCLI_PYTHON validated as a real executable path AND within expected venv directories

## Original Implementation (Phase 1, string-based — with known vulnerabilities)

```python
def _is_safe_path(path: str) -> bool:
    if '..' in path or path.startswith('/'):  # bypass: %2e%2e, ../x/../../y
        return False
    if not path or re.search(r'[^\w\-./_ ]', path):  # breaks Unicode paths
        return False
    return True

def _sanitize_input(input_str: str) -> str:
    sanitized = re.sub(r'[^\w\-./_ ]', '', input_str)  # strips Unicode silently
    while '..' in sanitized:                              # bypassable: a....b → ab
        sanitized = sanitized.replace('..', '')
    sanitized = sanitized.replace('`', '').replace('$', '').replace(';', '')
    if len(sanitized) > 1024:
        sanitized = sanitized[:1024]
    return sanitized
```

**Known bypass vulnerabilities (from cross-AI review):**

| Bypass | Method |
|--------|--------|
| Encoded traversal | `%2e%2e` passes `'..' in path` check |
| Nested collapse | `a....b` → strip `..` → `ab` — path escapes directory |
| Slashed traversal | `../x/../../y` — `..` present but after iterative strip escapes |
| Unicode path breakage | `project/données/train` → stripped to `project/donnes/train` |
| PowerShell metachar | `&`, `%VAR%`, `\|` not covered by bash-specific char strip |

**Fix applied in Phase 4:** Commit `4d3df52` added blocking of path components starting with
`.` (broader than just `..`). This improved but did not fully resolve the bypass vulnerabilities.

**Removed in Phase 5:** Commit `eb0a1bd` removed both functions from `mmcli/cli.py`.

### Task 1: Restore _is_safe_path() using semantic path resolution
<files>mmcli/cli.py (or mmcli/security.py)</files>
<action>
Restore and improve _is_safe_path() using pathlib semantics instead of string checks:

```python
from pathlib import Path

def _is_safe_path(path: str, base_dir: Path | None = None) -> bool:
    if not path or not path.strip():
        return False
    try:
        resolved = Path(path).resolve()
        anchor = base_dir or Path.cwd()
        return resolved.is_relative_to(anchor)
    except (ValueError, OSError):
        return False
```

Apply to all --project, --dataset, --output-dir, and file path arguments.
</action>

### Task 2: Restore _sanitize_input() with allowlist validation

```python
def _sanitize_input(input_str: str, max_length: int = 1024) -> str:
    if not isinstance(input_str, str):
        input_str = str(input_str)
    if len(input_str) > max_length:
        raise ValueError(f"Input exceeds maximum length of {max_length} characters")
    return input_str  # trust subprocess argument array + shell=False for isolation
```

For known-structured inputs (device IDs, task types), validate against the registry
allowlist rather than stripping characters.

## Threat Model

| Threat | Original Mitigation | Status | Target Mitigation |
|--------|---------------------|--------|------------------|
| Path traversal (REQ-SEC-01) | String `'..' in path` check | REMOVED in Phase 5 | `pathlib.resolve().is_relative_to()` |
| Command injection (REQ-SEC-02) | Char strip + shell=False | PARTIAL (shell=False remains) | shell=False + argument arrays (shell=False already enforced) |
| Buffer overflow (REQ-SEC-03) | 1024-char truncation | REMOVED in Phase 5 | ValueError on length exceeded |
| Env var manipulation | os.path.isfile(MMCLI_PYTHON) | UNKNOWN (needs audit) | Validate within expected venv root |
| Unicode path breakage | None (regex strips silently) | N/A | pathlib handles Unicode natively |

## Success Criteria

- `_is_safe_path("../../../etc")` returns False (semantic check, not string check)
- `_is_safe_path("myproject/données/train")` returns True (Unicode paths accepted)
- `_sanitize_input("x" * 1025)` raises ValueError
- All subprocess calls use `shell=False` (audit confirms)
- `pytest test_security_fixes.py -v` passes (no import errors)

## Restoration Required

The following work is required to restore Phase 1 security guarantees lost in Phase 5:

1. Restore `_is_safe_path()` using `pathlib.resolve().is_relative_to()` (not string ops)
2. Restore `_sanitize_input()` with length enforcement and allowlist for structured inputs
3. Re-wire both functions into path-accepting CLI arguments in `mmcli/cli.py`
4. Fix `test_security_fixes.py` import path
5. Run full security test suite to confirm guards work end-to-end

This work is tracked as a future phase item (suggested: new security-fix phase or Phase 4
supplement). The regression was introduced silently — no commit note mentioned removing guards.
