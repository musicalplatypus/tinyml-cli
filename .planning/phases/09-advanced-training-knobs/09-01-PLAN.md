# Plan 09-01: Add --nn-feature-extraction + --gof-test Flags + Builder Wiring

## Objective

Expose two modelmaker training parameters that are currently config-file-only:

- `nn_for_feature_extraction` (timeseries `data_processing_feature_extraction` section)
- `gof_test` (timeseries `data_processing_feature_extraction` section)

## Background

From `tinyml_modelmaker.ai_modules.timeseries.params.init_params()`:

```
data_processing_feature_extraction=dict(
    feature_extraction_name=None,
    nn_for_feature_extraction=False,   ← no CLI flag
    gof_test=False,                    ← no CLI flag
    ...
)
```

`nn_for_feature_extraction=True` enables a trainable neural feature extractor in place of
the classical signal processing pipeline (FFT bins, etc.). Useful when classical FE doesn't
generalise to the user's dataset.

`gof_test=True` runs a goodness-of-fit statistical test on the feature distribution during
training. Niche but useful for domain validation before committing to long training runs.

**Phase 8 dependency note:** The `--dataset-preset` flag (added in Phase 8) must already
exist in `_add_training_args` before this plan executes. Phase 8's addition goes immediately
after `--feature-extraction`; this plan's flags go after `--dataset-preset`.

### Task 3: Wire both flags into builder.py

<read_first>
- mmcli/builder.py (build_config, lines 173–185 — the FE name wiring and the dataset_preset
  wiring added by Phase 8 immediately after the FE name _set call)
</read_first>

<action>
In `build_config`, locate the FE section and the Phase 8 `dataset_name` wiring:

```python
_set(config, "data_processing_feature_extraction", "feature_extraction_name", ...)
_set(config, "dataset", "dataset_name", ...)  # Phase 8 addition
```

Immediately after the `dataset_name` line, add:

```python
if getattr(args, "nn_feature_extraction", False):
    config["data_processing_feature_extraction"]["nn_for_feature_extraction"] = True

if getattr(args, "gof_test", False):
    config["data_processing_feature_extraction"]["gof_test"] = True
```

Use `getattr(..., False)` so the builder doesn't fail when called from contexts where
these args are absent (compile, info, init subcommands that don't add training args).
Only inject the key when the flag is True — omitting the False case preserves modelmaker
defaults.
</action>

<acceptance_criteria>
- When `args.nn_feature_extraction=True`:
  `config["data_processing_feature_extraction"]["nn_for_feature_extraction"] == True`
- When `args.nn_feature_extraction=False` (default):
  `"nn_for_feature_extraction"` key is NOT in `config["data_processing_feature_extraction"]`
- Same pattern for `gof_test`
- `python -c "from mmcli.builder import build_config; print('ok')"` exits 0
</acceptance_criteria>
