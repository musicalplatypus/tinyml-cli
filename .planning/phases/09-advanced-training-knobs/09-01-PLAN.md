# Plan 09-01: Add --nn-feature-extraction + --gof-test Flags + Builder Wiring

## Objective

Expose two modelmaker training parameters that are currently config-file-only:

- `nn_for_feature_extraction` (timeseries `data_processing_feature_extraction` section)
- `gof_test` (timeseries `data_processing_feature_extraction` section)

## Background

From `tinyml_modelmaker.ai_modules.timeseries.params.init_params()`:

```python
data_processing_feature_extraction=dict(
    feature_extraction_name=None,
    nn_for_feature_extraction=False,   # ← no CLI flag
    gof_test=False,                    # ← no CLI flag
    ...
)
```

`nn_for_feature_extraction=True` enables a trainable neural feature extractor as a prefix
to the classification/regression head instead of classical signal processing (FFT bins, etc.).
Useful when the classical FE doesn't generalise to the user's dataset.

`gof_test=True` runs a goodness-of-fit statistical test on the feature distribution during
training. Niche but useful for domain validation before committing to long training runs.

## Tasks

### Task 1: Add --nn-feature-extraction flag to training args

<read_first>
- mmcli/cli.py (_add_training_args function, near the --feature-extraction and --dataset-preset args)
</read_first>

<action>
In `_add_training_args`, after the `--dataset-preset` block, add:

```python
group.add_argument(
    "--nn-feature-extraction",
    dest="nn_feature_extraction",
    action="store_true",
    default=False,
    help=(
        "Use a trainable neural network as the feature extractor instead of\n"
        "the default classical signal-processing pipeline (FFT bins, etc.).\n"
        "Timeseries tasks only. Increases model size and training time."
    ),
)
```
</action>

<acceptance_criteria>
- `python -m mmcli train --help | grep -A3 "nn-feature-extraction"` shows the flag
- `python -m mmcli run --help | grep "nn-feature-extraction"` exits 0
</acceptance_criteria>

### Task 3: Wire both flags into builder.py

<read_first>
- mmcli/builder.py (the build_config function, the data_processing_feature_extraction block)
</read_first>

<action>
In `build_config`, locate the block that wires `feature_extraction_name` into the config.
After the existing FE name + dataset preset wiring, add:

```python
if getattr(args, "nn_feature_extraction", False):
    config.setdefault("data_processing_feature_extraction", {})
    config["data_processing_feature_extraction"]["nn_for_feature_extraction"] = True

if getattr(args, "gof_test", False):
    config.setdefault("data_processing_feature_extraction", {})
    config["data_processing_feature_extraction"]["gof_test"] = True
```

Use `getattr(..., False)` so the builder doesn't fail when called from contexts where these
args are absent (e.g. `compile` subcommand).
</action>

<acceptance_criteria>
- When `args.nn_feature_extraction=True`, `config["data_processing_feature_extraction"]["nn_for_feature_extraction"] == True`
- When `args.nn_feature_extraction=False` (default), key is NOT injected (preserves modelmaker default)
- Same pattern for `gof_test`
- `python -c "from mmcli.builder import build_config; print('ok')"` exits 0
</acceptance_criteria>
