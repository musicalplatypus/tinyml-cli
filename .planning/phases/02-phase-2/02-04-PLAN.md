## Test Strategy
1. Mock subprocess.run for CCS/dslite commands **with platform-aware routing:**
   ```python
   def platform_mock_factory(cmd, **kwargs):
       if sys.platform == "win32":
           # dslite.exe path patterns
           ...
       elif sys.platform == "darwin":
           # CCS.app launcher path patterns
           ...
       else:
           raise FileNotFoundError("CCS not found on Linux CI")
   @patch('subprocess.run', side_effect=platform_mock_factory)
   ```
2. Use `pytest tmp_path` fixture (not manual tempfile) for SDK/artifact directories —
   guarantees teardown on test failure, avoids leaked fixtures in CI
3. Test device family detection for all supported devices
4. Test SDK root detection with glob patterns
5. Test artifact location with various run directories
6. Test project creation flow (copy, validate timestamps)

**Cross-AI review flags (HIGH):** Windows/macOS/Linux subprocess behavior differs for
CCS/dslite tools. Tests that pass on macOS may silently fail on Windows CI without
per-platform mock routing. Add `@pytest.mark.skipif(sys.platform != "win32", reason="Windows only")`
guards for Windows-specific path patterns.
