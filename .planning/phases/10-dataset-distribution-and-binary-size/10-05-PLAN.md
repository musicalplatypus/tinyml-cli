## Background

Two existing statements become factually wrong. `README.md:736` says:

```
| `MMCLI_DATASETS` | bundled `example_datasets/` | Override directory containing example dataset zips |
```

After D-2 only the 18 KB audio set is bundled, so both the stated default and the word
"Override" mislead. `README.md:507` shows `export MMCLI_DATASETS=...` without explaining that
it now also disables fetching entirely.

### The offline recipe has ten steps' worth of datasets and only nine URLs (review finding F-4)

An earlier draft told air-gapped users to "download the ten assets once". Only nine are
downloadable. `generic_audio_classification.zip` is locally authored, has no TI upstream, and
exists only in this repo and inside the binary. A user following that recipe literally ends up
with a directory of nine zips, `MMCLI_DATASETS` set, and one dataset that silently fails —
which is precisely the outcome REQ-DATA-04 exists to prevent.

`mmcli datasets path generic_audio_classification` prints the bundled copy's location, so the
tenth is obtainable from the binary itself without a repo checkout. That is the step the
recipe was missing.

### The rename matters in the recipe

Five local names differ from TI's (`fan_blade_fault.zip` is published as
`fan_blade_fault_dsi.zip`, `mnist_image_classification.zip` as `mnist_classes.zip`,
`pir_detection.zip` as `pir_detection_classification_dsk.zip`, `arc_fault_classification.zip`
as `arc_fault_classification_dsi.zip`, `ecg_classification.zip` as
`ecg_classification_2class.zip`). A user who fetches the URLs through a browser or proxy gets
TI's names, and `MMCLI_DATASETS` resolves by the *local* name. Recommending the
`datasets pull` + copy-from-cache route avoids the trap entirely, because the cache is already
keyed by local filename — say so, and give the mapping only as a fallback for people whose
proxy forces manual downloads.
