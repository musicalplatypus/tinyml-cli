## The diagnosis is already done — do not re-derive it

`10-UAT.md` §Gaps carries the root cause with file:line evidence for both gaps. This plan
implements the fix. Do not re-run the UAT tests to "confirm the gap" before starting.

**Gap 1, exactly.** `mmcli/datasets.py:745-760`: on a `force=False` pull with a cache entry
whose sha256 does not match, `fetch_dataset` unlinks the file and falls through to
`_download_to_cache` **without printing anything**. `mmcli/cli.py:1610` then prints the same
`✓ '{name}' available at: {path}` it prints for a clean cache hit. Note that
`_resolve_dataset_zip` (`datasets.py:403-408`) *does* warn on the same condition — `pull`
does not go through that function, which is why the warning never appears.

## Locked constraint: D-5 must not be weakened

`10-CONTEXT.md` D-5 is locked: mmcli auto-fetches only when stderr is a TTY, and suppresses
its tqdm progress bar on a non-TTY. This plan does **not** touch that.

- `--progress-json` changes the *format of reporting during a transfer the caller explicitly
  asked for*. It never enables a fetch, anywhere.
- `stderr_is_tty()` remains the sole gate on auto-fetch. The flag must not appear anywhere in
  that decision path.
- Without the flag, non-TTY output is unchanged.
- With the flag, the tqdm bar is suppressed **regardless of TTY** — two progress renderers
  interleaved on one stream produces garbage for both.
- The flag lands on `datasets pull` only. Do **not** add it to `init --dataset`; nothing in
  either gap needs it there and `init`'s auto-fetch is the exact surface D-5 governs.

The integrity-repair WARNING (Task 1) is **not** progress output and is **not** TTY-gated. It
is an integrity event and must always be emitted — including on a pipe, which is precisely
where PlatypusStudio will see it.

## The event schema is a cross-repo contract

Plan 10-12 decodes this in Swift. Emit exactly this, newline-delimited JSON, one object per
line, on **stderr**, flushed per line:

```
{"v":1,"event":"integrity-repair","dataset":"<name>","total_bytes":<int>}
{"v":1,"event":"start","dataset":"<name>","total_bytes":<int>}
{"v":1,"event":"progress","dataset":"<name>","bytes":<int>,"total_bytes":<int>}
{"v":1,"event":"result","dataset":"<name>","outcome":"<literal>","total_bytes":<int>}
```

Guarantees the Swift side is allowed to rely on, and which tests must pin:

- Every object carries `"v":1` and `"dataset"`.
- `integrity-repair`, when it occurs, precedes `start`.
- At most one `start`; `progress` only ever follows a `start`.
- `result` is always the last event and is emitted only on success. `outcome` is one of
  exactly `cache-hit`, `downloaded`, `forced-redownload`, `integrity-repair`.
- On failure no `result` is emitted; the CLI's existing `ERROR: ...` line and non-zero exit
  are unchanged.
- **No filesystem path, URL, hostname or environment value ever appears in an event.** Only a
  dataset name and byte counts. `_download_to_cache` knows the URL and the cache dir — neither
  goes into the stream.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mirror bytes → local cache | untrusted network bytes are written to disk and later extracted |
| local cache → CLI success report | on-disk state that may have been tampered with becomes a user-facing claim |
| mmcli stderr → an external tool's parser | a machine-readable stream crosses a process boundary into PlatypusStudio |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-11-01 | Repudiation | `fetch_dataset` silent cache repair | mitigate | unconditional stderr WARNING naming expected and actual digests, plus a distinct `REPAIRED` success line and an `integrity-repair` event; guarded by a subprocess-level test and mutation-tested (Task 1) |
| T-10-11-02 | Information disclosure | `--progress-json` event stream | mitigate | events carry only `v`, `event`, `dataset`, `bytes`, `total_bytes`, `outcome` — never a path, URL, hostname or environment value; asserted by an explicit test (Task 2) |
| T-10-11-03 | Denial of service | unbounded event volume on a pipe | mitigate | `progress` throttled to 200 ms / 1 MiB, whichever comes first (Task 2) |
| T-10-11-04 | Tampering | erosion of the D-5 auto-fetch policy | mitigate | `--progress-json` is opt-in, `pull`-only, and absent from the auto-fetch decision path; a regression test asserts non-flagged output emits no JSON and that non-TTY `init --dataset` still refuses (Task 2) |
| T-10-11-05 | Spoofing | substituted mirror bytes | accept | unchanged from 10-02/10-03 — sha256 before the atomic rename, closed cross-host redirect allowlist. This plan alters reporting only and must not touch that code |
| T-10-11-06 | Tampering | exit code masking a real failure | accept | an integrity repair exits 0 by design because the repair succeeded; a *failed* repair still raises and exits 1 through the existing handler |
| T-10-11-SC | Tampering | dependency additions | accept | no package installs — `json`, `time` and `sys` from the standard library only. If any step appears to need an install, stop: `10-RESEARCH.md`'s Package Legitimacy Audit does not cover it |
</threat_model>
