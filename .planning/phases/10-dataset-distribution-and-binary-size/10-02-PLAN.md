# Plan 10-02: Registry url/sha256, Cache Layer, `mmcli datasets pull`

## Objective

Let datasets be fetched on demand and cached, so the binary no longer has to carry them and
new datasets can ship without a new release.

**Blocked on a human decision:** the hosting location (see Phase PLAN "Open decisions").
`autonomous: false` — do not invent a URL.

## Background

`mmcli/datasets.py` already provides the seam:

```python
def _datasets_dir() -> str:
    env = os.environ.get("MMCLI_DATASETS")
    if env and os.path.isdir(env):
        return env
    return os.path.join(os.path.dirname(__file__), "example_datasets")
```

`DATASET_REGISTRY` holds one record per dataset (`filename`, `task_types`, `module`,
`description`) and `extract_dataset()` is the single point that opens a zip. There is
currently no download path of any kind.

The change is strictly additive: `MMCLI_DATASETS` and the bundled directory keep their
existing precedence, so every current invocation behaves exactly as before.

## Tasks

### Task 1: Extend the registry

<read_first>
- mmcli/datasets.py (`DATASET_REGISTRY`, all 10 entries)
</read_first>

<action>
Add two optional keys to each record: `url` (str) and `sha256` (lowercase hex str).

Both optional, but coupled — a record with `url` and no `sha256` is a configuration error
and must raise at load, not at download time. Add a module-level consistency check so the
invariant is enforced where it is cheap to see.

Leave both unset for now; 10-03 fills them once hosting is decided.
</action>

<verify>
A registry entry with `url` but no `sha256` raises a clear error on import.
</verify>

### Task 2: Cache directory + resolution order

<read_first>
- mmcli/datasets.py (`_datasets_dir`, `extract_dataset`)
</read_first>

<action>
Add `_cache_dir()` returning `~/.cache/mmcli/datasets` (honour `XDG_CACHE_HOME` when set),
created lazily with `exist_ok=True`.

Change dataset resolution to try, in order:

1. `MMCLI_DATASETS`
2. bundled `example_datasets/`
3. cache dir
4. download (only if `url` present and network use is permitted for this call)

The cache sits *below* the env var and the bundle deliberately: a user who has pinned
`MMCLI_DATASETS` for an air-gapped or reproducible setup must never be silently overridden
by a stale cached copy.
</action>

<verify>
With a zip present in all three locations, the env var wins; with it unset, the bundle wins;
with neither, the cache is used.
</verify>

### Task 3: Download with mandatory verification

<read_first>
- mmcli/datasets.py
- mmcli/cli.py (how other long operations report progress; reuse `tqdm`, already a declared dependency)
</read_first>

<action>
Implement `fetch_dataset(name, *, force=False) -> str`.

Requirements, each of which is a real failure mode rather than ceremony:

- Download to a temp file in the cache dir, verify sha256, then atomically `os.replace()`
  into place. A partial or corrupt file must never appear at the final path, because the
  next run would treat it as a valid cache hit.
- On checksum mismatch: delete the temp file, raise with both expected and actual digests.
- Do not follow redirects to a different host without surfacing it; reject non-HTTPS URLs.
- Show progress via `tqdm` when stderr is a TTY, and stay silent otherwise so CI logs are
  not flooded.
- Never auto-download when `MMCLI_DATASETS` is set — that variable signals a managed
  environment.

Use `urllib.request` from the stdlib. `requests` is not a declared dependency and adding one
to shrink a binary would be self-defeating.
</action>

<verify>
Unit tests with a local HTTP server: happy path caches and returns the path; truncated body
raises and leaves the cache empty; wrong checksum raises and leaves the cache empty; a second
call with a warm cache performs no request.
</verify>

### Task 4: `mmcli datasets` subcommand

<read_first>

<action>
Add a `datasets` subcommand with:

- `mmcli datasets pull <name>` — fetch and verify; `--force` re-downloads
- `mmcli datasets path <name>` — print the resolved path and exit non-zero if unavailable

`path` exits non-zero for an unavailable dataset.
</verify>

## Success Criteria

- Fetch → verify → cache → reuse works end to end for at least one real dataset
- Corrupt/truncated downloads fail loudly and leave no cache entry
- `MMCLI_DATASETS` set ⇒ zero network calls, in every code path
- `mmcli init --dataset <bundled>` still works with no network and no cache

## Risks

- **Hosting reachability.** Any remote source is unreachable for some TI/corporate users.
  `MMCLI_DATASETS` is the documented escape hatch and must be tested, not just described.
- **Checksum drift.** If a hosted zip is ever regenerated, its digest changes and every
  client breaks. Treat published datasets as immutable; publish a new name instead.
