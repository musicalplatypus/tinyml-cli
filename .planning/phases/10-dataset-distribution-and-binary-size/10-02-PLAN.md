# Plan 10-02: Registry Versioning, Cache Layer, `mmcli datasets pull`

## Objective

Let datasets be fetched from GitHub Release assets on demand, pinned to a release tag, and
cached — so the binary no longer carries them and a dataset can differ per release.

Decisions D-1/D-2/D-3 are resolved (see `10-RESEARCH.md`), so this plan is unblocked.

## Background

`mmcli/datasets.py` already has the seam:

```python
def _datasets_dir() -> str:
    env = os.environ.get("MMCLI_DATASETS")
    if env and os.path.isdir(env):
        return env
    return os.path.join(os.path.dirname(__file__), "example_datasets")
```

`DATASET_REGISTRY` holds one record per dataset (`filename`, `task_types`, `module`,
`description`); `extract_dataset()` is the only place a zip is opened. There is no download
path today.

The change is additive — `MMCLI_DATASETS` and the bundled directory keep their existing
precedence, so nothing regresses for managed environments.

**Versioning (D-3).** Assets live on existing release tags, e.g.

```
https://github.com/musicalplatypus/tinyml-cli/releases/download/PlatypusCLI_1.1.2_Release/fan_blade_fault.zip
```

A module-level `DATASETS_DEFAULT_TAG` supplies the tag; a registry entry may override it with
its own `tag` when that dataset changed independently of the release.

## Tasks

### Task 1: Registry gains tag/sha256, URL is derived

<read_first>
- mmcli/datasets.py (`DATASET_REGISTRY`, all 10 entries)
</read_first>

<action>
Add module constants:

```python
DATASETS_REPO = "musicalplatypus/tinyml-cli"
DATASETS_DEFAULT_TAG = "PlatypusCLI_1.1.2_Release"   # bump per release
```

Add two optional per-entry keys: `tag` (defaults to `DATASETS_DEFAULT_TAG`) and `sha256`.

Derive the URL rather than storing it — a hand-written URL per entry is ten places to get the
tag wrong:

```python
def dataset_url(name: str) -> str:
    e = DATASET_REGISTRY[name]
    tag = e.get("tag", DATASETS_DEFAULT_TAG)
    return f"https://github.com/{DATASETS_REPO}/releases/download/{tag}/{e['filename']}"
```

Enforce at import that every entry has a `sha256` — a downloadable dataset without a digest
is a configuration error, and failing at import surfaces it where it is cheap to see rather
than mid-download.
</action>

<verify>
<automated>
pytest tests/test_datasets_download.py -k "registry" -q
</automated>
Asserts: every entry has sha256; `dataset_url()` uses the default tag; an entry with an
explicit `tag` overrides it; an entry missing sha256 raises at import.
</verify>

### Task 2: Tag-scoped cache and resolution order

<read_first>
- mmcli/datasets.py (`_datasets_dir`, `extract_dataset`)
</read_first>

<action>
Add `_cache_dir(tag)` returning `~/.cache/mmcli/datasets/<tag>` (honour `XDG_CACHE_HOME`),
created lazily.

**The tag must be part of the path.** A flat cache would let an mmcli upgrade silently reuse
a dataset from an older release — the exact failure D-3 exists to prevent.

Resolution order becomes:

1. `MMCLI_DATASETS`
2. bundled `example_datasets/` (empty after 10-03; retained for local builds)
3. `~/.cache/mmcli/datasets/<tag>/`
4. download

The cache sits *below* the env var deliberately: a user who pinned `MMCLI_DATASETS` for an
air-gapped or reproducible setup must never be overridden by a cached copy.
</action>

<verify>
<automated>
pytest tests/test_datasets_download.py -k "resolution or cache_key" -q
</automated>
Asserts: env var wins over bundled and cache; cache path contains the tag; two tags cache
independently.
</verify>

### Task 3: Download with mandatory verification

<read_first>
- mmcli/datasets.py
- mmcli/cli.py (progress conventions — `tqdm` is already a declared dependency)
</read_first>

<action>
Implement `fetch_dataset(name, *, force=False) -> str`.

Each requirement below is a real failure mode, not ceremony:

- Download to a temp file **in the same directory**, verify sha256, then `os.replace()`.
  Same-directory keeps the rename atomic; a partial file at the final path would become a
  poisoned cache hit on the next run.
- Checksum mismatch: delete the temp file, raise reporting expected and actual digests.
- Reject non-HTTPS URLs. Surface cross-host redirects rather than following silently.
- `tqdm` progress only when stderr is a TTY, so CI logs stay clean.
- **Never auto-download when `MMCLI_DATASETS` is set** — that variable signals a managed
  environment (REQ-DATA-03).
- A 404 must say the dataset is not published for that tag, naming the tag. This will be the
  common error while assets are still being uploaded.

Use stdlib `urllib.request`. Adding `requests` to shrink a binary is self-defeating.
</action>

<verify>
<automated>
pytest tests/test_datasets_download.py -k "fetch" -q
</automated>
Against a local HTTP server: happy path caches and returns the path; truncated body raises
and leaves the cache empty; wrong digest raises and leaves the cache empty; warm cache issues
no request; `MMCLI_DATASETS` set issues no request; non-HTTPS URL is refused.
</verify>

## Success Criteria

- `mmcli datasets pull <name>` fetches from the tag-pinned release URL, verifies sha256,
  caches under the tag, and a second call performs no network request
- Corrupt, truncated, or wrong-digest downloads fail loudly and leave no cache entry
- `MMCLI_DATASETS` set ⇒ zero network calls in every path
- `datasets list --format json` is stable and machine-parseable

## Risks

- **Reachability.** Any remote source is unreachable for some corporate/air-gapped users.
  `MMCLI_DATASETS` is the escape hatch and must be tested, not merely documented.
- **Digest drift.** Republishing an asset under an existing tag breaks every cached client.
  Treat published assets as immutable; publish under a new tag instead.
