## Background

This plan was split out of 10-02 because that plan had four tasks and would have run past its
context budget. It also isolates the one decision in this phase that two plans disagreed
about.

### Decision D-5 — who is allowed to start a download (resolves review finding F-5)

The earlier draft had `mmcli init --dataset X` auto-fetch whenever the dataset was missing,
while 10-04 disabled the GUI's Create button behind an explicit "Download (54 MB)" click. Both
cannot own the decision, and mmcli auto-fetching underneath a GUI is precisely the silent
multi-megabyte stall REQ-UX-01 exists to prevent.

Three options were considered:

| Option | Behaviour | Why not / why |
|---|---|---|
| A — never auto-fetch | `init` on a missing dataset always errors with "run `mmcli datasets pull X`" | Safest and simplest, but makes the common interactive case a two-command dance for no safety gain when a human is watching |
| B — always auto-fetch | `init` downloads whenever needed | Rejected: reintroduces the silent stall under the GUI and in CI, which is the failure REQ-UX-01 names |
| C — auto-fetch only when stderr is a TTY, with explicit overrides | Interactive terminal downloads with a progress bar; pipes, CI and GUI subprocesses get an actionable error | **Chosen** |

Option C is adopted, with the principle stated plainly: **mmcli never starts a
multi-megabyte transfer it cannot narrate.** `stderr.isatty()` is already the predicate 10-02
uses to decide whether to show a `tqdm` progress bar, so reusing it is not an extra heuristic
— it makes progress and permission the same question. If we cannot show progress, we must not
download.

The TTY test is a heuristic, and heuristics need an escape hatch in both directions, so the
decision precedence is:

1. `MMCLI_DATASETS` set → never fetch (REQ-DATA-03, hard, overrides everything below)
2. `--no-fetch` or `MMCLI_AUTO_FETCH=0` → never fetch
3. `--fetch` or `MMCLI_AUTO_FETCH=1` → fetch regardless of TTY
4. otherwise → fetch if and only if `sys.stderr.isatty()`

A CI job that genuinely wants the download passes `--fetch` and gets it deterministically,
without pty tricks. PlatypusStudio's `ProcessRunner` pipes stderr, so it lands on rule 4 and
gets the error — which is exactly what makes 10-04's explicit affordance the only path to a
download in the GUI, with no coordination between the two repos beyond this rule.

Consequence for 10-04: its Task 2 verification must assert this, not assume it.

### The JSON interface is a commitment, not a convenience

`--format json` on `list` is required, not optional. Plan 10-04 parses it; the previous
attempt at parsing mmcli's human-formatted table is what made `DatasetListParser` fragile. The
key set (`name`, `version`, `state`, `bytes`, plus the existing descriptive fields) is an
interface this plan owns and 10-04 depends on, so it is specified here rather than discovered
there.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI arguments → dataset name → URL | a name from argv must not steer a request |
| GUI subprocess → mmcli | PlatypusStudio invokes mmcli with user-chosen arguments and consumes its stdout |
| mmcli stdout → machine parser | 10-04 parses this output; malformed or non-deterministic output is a correctness problem for the consumer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-06-01 | Spoofing | `datasets pull <name>` argument | mitigate | resolve through `DATASET_REGISTRY`; unknown names exit non-zero listing valid names, never reaching URL composition |
| T-10-06-02 | Denial of service | unattended transfer under a GUI or CI | mitigate | D-5 policy: no implicit fetch unless stderr is a TTY or `--fetch` is explicit |
| T-10-06-03 | Repudiation | air-gap defeat through the CLI | mitigate | `MMCLI_DATASETS` blocks fetching at the policy layer and again inside `fetch_dataset`, so neither layer alone is load-bearing |
| T-10-06-04 | Tampering | consumer parsing a human table | mitigate | `--format json` is a committed interface with a contract test, so 10-04 never parses prose |
| T-10-06-SC | Tampering | npm/pip/cargo installs | accept | no new package-manager installs; argparse and json are stdlib and `tqdm` is already declared |
</threat_model>
