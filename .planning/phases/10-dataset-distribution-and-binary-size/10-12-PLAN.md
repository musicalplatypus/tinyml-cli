## The contract this plan decodes

From 10-11, newline-delimited JSON on **stderr**, one object per line:

```
{"v":1,"event":"integrity-repair","dataset":"<name>","total_bytes":<int>}
{"v":1,"event":"start","dataset":"<name>","total_bytes":<int>}
{"v":1,"event":"progress","dataset":"<name>","bytes":<int>,"total_bytes":<int>}
{"v":1,"event":"result","dataset":"<name>","outcome":"<literal>","total_bytes":<int>}
```

`outcome` is one of `cache-hit`, `downloaded`, `forced-redownload`, `integrity-repair`.
`result` is always last and is emitted only on success. **Do not re-derive this schema from
mmcli's source** — read the committed description in `README.md` §Datasets, and pin the shapes
in tests against literal fixture strings so a schema change breaks a test rather than the app.

## Scope decisions, made deliberately rather than left implicit

- **The Manage Datasets library (10-09) is IN scope for progress, OUT of scope for a success
  confirmation.** Its rows already flip `.downloadable` → `.cached` and render "Downloaded"
  with a Remove button, which is a standing confirmation; the New Project sheet's rows vanish,
  which is the actual defect. Fixing progress in both is a small symmetric change and is what
  makes the 10-09 cancel-mid-transfer check reachable at all (see Task 3 step 8).
- **`DatasetCatalog.swift` is not modified.** The new type goes in its own file so 10-09's
  `DatasetCatalogTests` and `DatasetLibraryTests` stay untouched and any breakage there is a
  real regression rather than a merge artifact.
- **No new package dependencies in either repository.** Foundation, SwiftUI and existing
  MMCLIKit only.

## The view layer has no automated coverage, and this plan does not pretend otherwise

`Package.swift` declares exactly one test target — `MMCLIKitTests`, depending only on
`MMCLIKit` — so no SwiftUI view in this package can be covered by a test today. Phase 11's
REQ-TEST-01 owns that structural gap; do not try to close it here.

The consequence for this plan is explicit: **all testable logic goes into MMCLIKit (Task 1),
and the view wiring (Task 2) is verified by a human at Task 3, not by a test.** Do not write a
test that exercises a helper resembling the view's code path and then describe the view as
covered. The phase already recorded that failure mode: a regression test once exercised helper
functions resembling the real path and passed against a binary that still had the bug.

Public API — define exactly this so Task 2 has no interpretation to do:

  `downloaded`, `forcedRedownload`, `integrityRepair`, `unrecognised`, and

  line that is not a `"v":1` transfer event — plain text, partial JSON, a future version, a
  missing key. It must never throw and never trap.
- `public struct DatasetTransferProgress: Equatable, Sendable` holding `totalBytes: Int?`,

  `logLines: [String]`, with computed `fraction: Double?` (nil until a `start` and when

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mmcli stderr → app decoder | an untrusted-length text stream from a subprocess drives UI state |
| decoded progress → SwiftUI render | parsed numbers become a bar value and a displayed string |
| user button press → subprocess argv | a dataset name chosen in a list becomes an argv element |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-12-01 | Repudiation | a completed download indistinguishable from a crash | mitigate | session-scoped confirmation line replaces the bare `EmptyView()` for a dataset downloaded in this session; verified at Task 3 steps 2 and 3 |
| T-10-12-02 | Tampering | malformed or hostile stderr driving UI state | mitigate | `DatasetTransferEventDecoder` is total — never throws, rejects unknown schema versions and missing keys, clamps `fraction` to `0...1`, keeps `bytesTransferred` monotonic (Task 1) |
| T-10-12-03 | Information disclosure | subprocess output rendered verbatim in the UI | accept | 10-11 guarantees events carry no path, URL or hostname, and non-event lines are mmcli's own user-facing text — the same material `explainDownloadFailure` has displayed since 10-04 |
| T-10-12-04 | Denial of service | unbounded `logLines` growth on a long or looping stream | mitigate | only non-event lines are retained and only the last is rendered; if a stream ever produces sustained non-event output, cap `logLines` rather than growing it without bound |
| T-10-12-05 | Elevation of privilege | dataset name reaching a subprocess | accept | unchanged from 10-09 — argv is an array through `ProcessRunner`, never a shell string, and only names mmcli itself listed are sent |
| T-10-12-06 | Denial of service | unauthorised background transfer | mitigate | `--fetch` is still never passed; `--progress-json` is a reporting flag and does not enable fetching. A grep gate in Task 2 asserts `--fetch` appears in neither view |
| T-10-12-SC | Tampering | dependency additions | accept | no package installs in either repository — Foundation, SwiftUI and existing MMCLIKit only. If any step appears to need a Swift package dependency, stop rather than adding one |
</threat_model>
