# Plan 10-03: Unbundle the TI Datasets

## Objective

Stop bundling the nine TI datasets, taking the binary from ~138.7 MB to roughly 14 MB.

Per D-1 they are fetched from TI rather than mirrored, so there is nothing to publish. Per
D-2 the one locally authored dataset (`generic_audio_classification.zip`, 18 KB, already
tracked in git) stays bundled.

## Background

`--add-data mmcli/example_datasets:mmcli/example_datasets` currently bakes 125 MB into the
binary:

| Dataset | Size |
|---------|------|
| fan_blade_fault.zip | 54 MB |
| mnist_image_classification.zip | 45 MB |
| arc_fault_classification.zip | 13 MB |
| ecg_classification.zip | 4.4 MB |
| generic_timeseries_anomalydetection.zip | 4.0 MB |
| generic_timeseries_classification.zip | 2.5 MB |
| pir_detection.zip | 1.5 MB |
| generic_timeseries_regression.zip | 888 KB |
| *(2 further small zips)* | — |

`--onefile` extracts the whole archive on **every launch**, so this is paid per invocation,
not once at install — which is why startup tracks payload size so closely.

Nine of these ten are byte-identical copies of files TI publishes (five under different
names); see the provenance table in `10-RESEARCH.md`. They are not at risk, which is why
this plan fetches rather than mirrors.

### Task 2: Stop bundling datasets

<read_first>
- build_macos.sh (the `--add-data` line and the `EXCLUDES` block added by 10-01)
- build_linux.sh
</read_first>

<action>
Replace the blanket `--add-data .../example_datasets:...` with one that stages only the
locally authored dataset, so the choice is explicit in the build rather than implied by
whatever happens to be on disk:

```bash
BUNDLED_DATASETS=(generic_audio_classification.zip)
```

Stage those into a temp dir and pass that to `--add-data`. A developer with the nine TI zips
sitting in their working tree must not accidentally ship a 138 MB binary.

Keep the directory in the source tree and keep `_datasets_dir()`'s bundled-path branch — a
developer running from source still resolves local zips, and `MMCLI_DATASETS` still works.
</action>

## Success Criteria

- All nine TI datasets reachable at their pinned URLs; ten digests recorded in the registry
- `dist/mmcli` ≤ 15 MB, startup < 2.5 s (3-run median)
- `mmcli init --dataset <any>` works from a clean cache with network
- With `MMCLI_DATASETS` set to a directory of the 10 zips, every `init --dataset` works with
  **zero** network access
- `mmcli init --dataset generic_audio_classification` works with no network and no cache
- Build-script comments state real numbers (user docs are 10-05)

## Rollback

Restoring the blanket `--add-data` line reverts to a fully bundled binary. The registry
`ti_name`/`sha256` fields are inert when the file is already present locally, so rollback
needs no code change — worth stating plainly, because it makes this cheap to try and undo.
