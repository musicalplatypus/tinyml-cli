## Background

`--add-data mmcli/example_datasets:mmcli/example_datasets` currently bakes 125 MB into the
macOS binary:

| Dataset | Bytes |
|---------|-------|
| fan_blade_fault.zip | 56,595,859 |
| mnist_image_classification.zip | 46,993,516 |
| arc_fault_classification.zip | 13,290,076 |
| ecg_classification.zip | 4,651,662 |
| generic_timeseries_anomalydetection.zip | 4,242,845 |
| generic_timeseries_classification.zip | 2,579,940 |
| pir_detection.zip | 1,579,936 |
| generic_timeseries_regression.zip | 906,660 |
| generic_timeseries_forecasting.zip | 71,053 |
| generic_audio_classification.zip | 18,371 |

`--onefile` extracts the whole archive on **every launch**, so this is paid per invocation,
not once at install — which is why startup tracks payload size so closely.

Per D-1 the nine TI datasets are fetched rather than mirrored, so there is nothing to publish.
Per D-2 the one locally authored dataset (`generic_audio_classification.zip`, 18 KB, already
tracked in git) stays bundled.

The registry digests are recorded by 10-02 Task 1, not here — they must exist before this plan
can verify anything.

### The three build scripts do not agree about `--add-data` (checked on disk, 2026-07-22)

Only `build_macos.sh` has an `--add-data` line at all. `build_linux.sh` and
`build_windows.ps1` have none, so the Linux and Windows release assets ship with *zero*
datasets today — including the 18 KB locally authored one, which has no upstream and therefore
cannot be fetched. On those two platforms `mmcli datasets path generic_audio_classification`
has nothing to point at, which breaks step 3 of 10-05's offline recipe and leaves REQ-DATA-04
unsatisfied for two of the three shipped artifacts.

This is a pre-existing divergence, not something unbundling introduces. It surfaces now because
D-2 makes "exactly one zip is bundled" a stated invariant, and an invariant that holds on one
of three platforms is the same class of defect as the `~10 MB` comment. Task 2 therefore
*adds* the staged allowlist to Linux and Windows rather than merely narrowing an existing line.

### Why Task 1 is a content check, not a reachability check (review finding F-3)

The earlier draft of this task issued HEAD requests. HEAD proves a URL resolves; it says
nothing about what it serves. Because the digests were computed from local files, the one
failure mode that breaks *every* user — TI serving different bytes at the pinned versioned
path than the flat path the provenance table compared against — is exactly what a HEAD check
cannot see. Four of the nine were spot-checked by hand during review; the other five were not,
and a gate that relies on someone having checked by hand is not a gate.

Platform details that do not transfer:

- **Separator.** PyInstaller's `--add-data` uses `:` on macOS/Linux and `;` on Windows. Passing
  the POSIX form on Windows yields a silently empty bundle, not an error, so `datasets path`
  would fail at runtime with no build-time signal. Write the Windows form as `;`.
- **Destination.** Keep the in-binary destination `mmcli/example_datasets` on every platform,
  because `_datasets_dir()` resolves that path — the staging source directory name is
  irrelevant, the destination is not.
- **PowerShell.** Add the data argument through the same array-splat used for `$ExcludeArgs`,
  not by interpolating into the backtick-continued command line. Create the temp directory with
  `New-Item -ItemType Directory` under `[System.IO.Path]::GetTempPath()` and remove it after
  the build; `Remove-Item -Recurse -Force` in a `finally` so a failed build does not leave it.
- **`--collect-submodules` / `--paths`.** `build_linux.sh` and `build_windows.ps1` lack both
  and use `--hidden-import` instead. Leave that difference alone — it is a working alternative
  and changing it here would mix an unrelated risk into the size change.

parametrises over the three build scripts to assert their `--exclude-module` flags; add

This exists because the runtime probe is not enough on its own. `test-cli.yml` builds no

tag. A regression would merge silently and surface when someone cuts a release. The exclusions
are source-tested on every push; the bundling must be held to the same standard, and for the
same reason: this phase's whole premise is that an invariant nothing runs is not an invariant.

Match on the parsed `--add-data` *argument*, not on a bare substring — the dataset name also
appears in comments and in the `BUNDLED_DATASETS` list, and a substring match would pass on a
script whose flag was deleted but whose comment survived. The `grep -c` hazard 10-01 Task 3
notes applies here identically.

## Rollback

Restoring the blanket `--add-data` line reverts macOS to a fully bundled binary, and raising
`scripts/binary_size_ceiling.txt` back to 152043520 keeps the guard consistent. The Linux and
Windows `--add-data` additions are new capability rather than a change, so rolling them back
means deleting them. The registry `ti_name`/`sha256` fields are inert when the file is already
present locally, so rollback needs no code change — worth stating plainly, because it makes
this cheap to try and undo.
