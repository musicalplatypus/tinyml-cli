# Plan 10-01: Enforce PyInstaller Exclusions + Size Regression Guard

## Objective

Stop PyInstaller bundling the training engine into the `mmcli` launcher, and add a guard so
the exclusion cannot silently disappear again.

## Background

`build_macos.sh` documents the intent at line 4:

```
# The binary is lightweight (~10 MB) because tinyml_modelmaker is NOT bundled.
```

Nothing enforced it. The generated `mmcli.spec` had `excludes=[]`, so PyInstaller's static
analysis followed three guarded probes and bundled their whole dependency trees:

| Site | Statement | Guarded by |
|------|-----------|------------|
| `mmcli/recommend.py:121` | `import tinyml_modelmaker` | `try/except ImportError: pass` |
| `mmcli/diagnose.py:131` | `import tinyml_modelmaker` | `try/except ImportError` |
| `mmcli/diagnose.py:208` | `import tvm` | `try/except ImportError` |

PyInstaller does not care that they are guarded — a reachable `import` is followed. The
other `import tinyml_modelmaker` occurrences (`info.py:40`, `compare.py:30`, `cli.py:218`)
are inside *string literals* sent to a subprocess, so they were never the problem.

Because all three real sites already handle `ImportError`, excluding the modules is
behaviour-preserving: the probes become the no-ops their `except` branches already expect.

Measured effect: 260.3 MB → 138.7 MB, startup ~6.2 s → ~5.2 s (3-run steady state).

**`numpy` and `pandas` must NOT be excluded** — `analyze.py::_row_count` imports them to
compute dataset statistics, and excluding them breaks `mmcli analyze`.

## Tasks

### Task 1: Add exclusions to the macOS build

<read_first>
- build_macos.sh (the `pyinstaller` invocation, and the `rm -rf ... mmcli.spec` line above it —
  the spec is regenerated each build and is gitignored, so the fix must live in the flags,
  not the spec)
</read_first>

<action>
Before the `pyinstaller` call, define the exclude list and expand it into `--exclude-module`
flags. Add the flags to the invocation.

```bash
EXCLUDES=(
    torch torchvision torchaudio
    tinyml_modelmaker tinyml_tinyverse tinyml_torchmodelopt tinyml_modelzoo
    tvm
    matplotlib scipy sklearn onnx onnxruntime
)
EXCLUDE_ARGS=()
for m in "${EXCLUDES[@]}"; do EXCLUDE_ARGS+=(--exclude-module "$m"); done
```

Include a comment explaining *why* — that mmcli reaches the engine via `MMCLI_PYTHON`
subprocesses, that the guarded probes are what drag the engine in, and that numpy/pandas are
deliberately retained.
</action>

<verify>
`bash build_macos.sh` succeeds; `ls -la dist/mmcli` is under 145 MB; the script's existing
"mmcli modules bundled" check still reports 17.
</verify>

### Task 2: Mirror the change in the Linux build

<read_first>
- build_linux.sh (confirm it has the same `pyinstaller` invocation shape as build_macos.sh)
</read_first>

<action>
Apply the identical exclude list. If the two scripts have diverged, prefer factoring the
list into a shared `build_excludes.txt` read by both over duplicating it — a list that has
to be edited twice will drift.
</action>

<verify>
Linux script passes shellcheck / `bash -n`. Do not claim a size result for Linux without
running it on Linux; if unavailable, state that it is untested on that platform.
</verify>

### Task 3: Regression guard

<read_first>
- tests/ (existing test layout and naming)
</read_first>

<action>
Add a test that reads the build scripts and asserts every entry of the expected exclude set
appears as an `--exclude-module` argument, and that `numpy` and `pandas` do **not**.

This is a source-level assertion deliberately, not a build-and-measure test: building the
binary takes minutes and needs PyInstaller, which is too heavy for the unit suite. The test
catches the actual failure mode — someone editing the invocation and dropping the flags.

If CI has a release job that produces the binary, additionally assert a size ceiling there
(fail above 45 MB once 10-03 lands; 145 MB until then).
</action>

<verify>
`pytest tests/test_build_config.py` passes. Deleting one `--exclude-module` flag makes it
fail.
</verify>

## Success Criteria

- `dist/mmcli` ≤ 145 MB after this plan (the dataset payload is 10-03's problem)
- `mmcli --version`, `init --list`, `info`, `analyze`, `diagnose` all still work
- Removing an exclusion from the build script fails the test suite
- No behavioural change to the three guarded probes

## Out of scope

Dataset unbundling (10-03) and the `cryptography`/`PIL` investigation — the latter needs a
dependency trace to confirm they are genuinely unused before excluding them.
