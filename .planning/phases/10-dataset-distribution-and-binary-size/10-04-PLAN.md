## Background

`NewProjectSheet` shells out to `mmcli init` to create a project from an example dataset.
Once 10-03 unbundles the large datasets, choosing `fan_blade_fault` on a machine with an empty
cache has nothing to extract.

The division of responsibility is deliberate: **mmcli owns the download, the app owns the
prompting.** mmcli is used headless and in CI and must work without a GUI, so the fetch logic
cannot live in the app. The app already invokes mmcli for every other operation, so calling
`mmcli datasets pull` keeps one mechanism rather than adding a second implementation that
could drift from it.

### What decision D-5 guarantees this plan (review finding F-5)

An earlier draft of 10-02 had `mmcli init --dataset X` auto-fetch whenever the dataset was
missing. That directly contradicted this plan's explicit-download affordance, and it is the
silent multi-megabyte stall REQ-UX-01 exists to prevent. D-5, recorded in 10-06, resolves it:
mmcli auto-fetches only when `stderr` is a TTY or `--fetch` is passed explicitly.

`ProcessRunner` pipes stderr, so every mmcli invocation from this app lands on the non-TTY
rule and gets a hard error naming the `datasets pull` command instead of a download. The app
therefore owns the prompting by construction, with no flag coordination needed.

**Do not pass `--fetch` from the app.** Doing so re-creates exactly the behaviour D-5 removed.
Task 3 verifies the guarantee rather than trusting it.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mmcli stdout → app JSON decoder | subprocess output is parsed and drives UI state |
| user selection → subprocess arguments | a dataset name chosen in the UI becomes an argv element |
| network transfer initiated from a GUI | a background transfer the user did not authorise is the failure REQ-UX-01 names |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-04-01 | Tampering | JSON decoding of mmcli output | mitigate | decode into a typed model with an explicit malformed state; never `try!`, never treat a decode failure as an empty catalog |
| T-10-04-02 | Elevation of privilege | dataset name passed to a subprocess | mitigate | pass argv as an array through `ProcessRunner` (no shell string), and only names that came from mmcli's own list |
| T-10-04-03 | Denial of service | unauthorised background transfer | mitigate | download only on explicit button press; D-5 guarantees mmcli will not fetch behind the app; Task 3 step 7 verifies it |
| T-10-04-04 | Repudiation | checksum failure shown as a generic error | mitigate | surface mmcli's own message so a substituted-bytes failure is distinguishable from an outage |
| T-10-04-SC | Tampering | SwiftPM dependency additions | accept | this plan adds no package dependencies; it uses existing MMCLIKit and Foundation only |
</threat_model>
